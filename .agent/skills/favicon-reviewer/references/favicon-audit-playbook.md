# Favicon Audit Playbook

## Best-Use Scenario

这份 playbook 适合“主题已经存在，现在要判断 favicon 到底像不像这个主题，并在尽量不动构图的前提下修正它”的任务。

它特别适合以下场景:

- 主题 CSS 已经成型，favicon 只是还没完全跟上
- 用户要求保留当前 favicon 的布局、轮廓、图形语义
- 需要逐个主题批量审查 favicon

默认不包括以下范围:

- `theme-color` 或浏览器外壳着色
- `apple-touch-icon`
- manifest / PWA 安装图标
- SEO 图标链路或站点图标分发完整性

除非用户明确提出，否则不要把 favicon 风格审查扩展到这些系统层资源。

## Step 1: Define The Theme Intent

先用不超过 5 个短点写清主题概念:

- 情绪
- 材质
- 光源
- 对比度目标
- 圆角 / 硬边气质

如果这一步说不清，后面的“像不像”就容易流于主观。

## Step 2: Read CSS In A Narrow Pass

不要一上来通读整份主题文件。先抓最可能影响 favicon 气质的 token:

1. 基底与面材质:
   `--bg-*`, `--surface-panel-*`, `--surface-floating-*`
2. 边框与高光:
   `--border-*`, `--overlay-sheen`
3. 主色轴:
   `--accent-*`, `--range-progress-*`, `--readout-value-*`
4. 深度语言:
   `--shadow-*`
5. 圆角倾向:
   `--radius-*`

目标不是抄 token，而是判断:
这个主题的 favicon 应该更像“深色面板上的局部高亮”，还是“高饱和主体图形”。

## Step 3:拆解 SVG 的视觉分工

读 SVG 时，先不要急着改。先把每个元素归类成下面几层:

- 主体底色
- 主体描边
- 内部高光
- 内部细节线 / 刻度
- 动势线 / 摆杆
- 节点 / 圆点 / 终点
- 额外装饰

如果一个 SVG 元素同时承担了两种语义，例如“机身既是主体又承担主题渐变展示”，通常就是后续违和感的来源。

## Step 4: Audit In This Order

1. 构图是否锁定
2. 主体是否像该主题的主材质
3. 描边是否像该主题的边框语言
4. 高光是否像该主题的反射语言
5. 主色、辅色、第三色是否分工清楚
6. 圆角或硬边气质是否被传递出来
7. 小尺寸下对比是否仍然成立
8. 到这里为止即可；
   不额外延伸去审查 `theme-color`、`apple-touch-icon`、manifest 或 PWA 图标，除非用户明确要求

## What To Look For

- 主题本体是深色玻璃，但 favicon 却把主体画成高亮渐变块
- 主题本体是哑光或纸感，但 favicon 高光过白、过亮、过数字感
- 主题明明是圆润 UI，favicon 却全是硬折角和生硬描边
- 主题明明是工业 / 终端 / 瑞士 / brutalism，favicon 却被柔化成软 UI
- 第三色在主题里只是点缀，但在 favicon 里抢了主体存在感
- SVG 为了“更有设计感”加了太多装饰，导致 16x16 下发糊

## Practical Heuristics

- 机身主体:
  默认优先参考 `--bg-primary` 和 `--surface-*`
  只有当主题本身就是“高饱和图形块”时，才考虑让主体直接吃亮色渐变
- 动势线:
  最适合承接主题里的主 accent 或读数渐变
  因为它面积小，允许更亮、更活跃
- 节点 / 圆点:
  默认跟主 accent 走
  第三色更适合放在远端节点或最小面积的点缀位
- 内部高光:
  优先使用带色温的半透明高光，而不是纯白
  冷色主题偏青白，暖色主题偏米白 / 奶白
- 描边:
  不是越深越稳
  应该像主题里的边框，而不是一条默认黑线
- 阴影 / 发光:
  favicon 通常不适合复制复杂 CSS shadow
  更适合把“发光感”翻译成渐变、边色和局部高光，而不是大量滤镜

## Radius Without Changing Geometry

当用户要求保留布局和轮廓时，不代表完全无法传递圆角气质。优先试这些方法:

- 给主体描边补 `stroke-linejoin="round"`
- 给线性元素补 `stroke-linecap="round"`
- 把内部高光从锐利切片改成更柔和的亮面
- 降低描边反差，让轮廓读起来不那么硬

不要在这种约束下直接新增圆角底板或重画大轮廓，除非用户明确允许。

## Common Mismatch Patterns

### Pattern 1: Too Neon

现象:
主题本身是深色面板 + 局部冷光，但 favicon 整体像霓虹招牌

常见原因:

- 整块主体使用高饱和渐变
- 主体和动势线同时过亮
- 第三色面积过大

常见修法:

- 把主体压回深色面材质
- 保留亮色在动势线和节点
- 让第三色只出现在收尾位置

### Pattern 2: Too Generic

现象:
favicon 看起来“没错”，但像系统默认图标，不像这个主题

常见原因:

- 高光使用纯白
- 描边使用默认深灰或纯黑
- 所有层都只是在用中性色

常见修法:

- 给高光加入主题色温
- 描边改用主题边框色系
- 在动势线或局部反光里引入主题主轴

### Pattern 3: Third Color Is Too Loud

现象:
紫、粉、橙这类第三色在 favicon 里过分显眼

常见原因:

- 主体渐变直接覆盖了第三色
- 最大的装饰节点使用了第三色
- 第三色和主色亮度差太小

常见修法:

- 把第三色从主体移到小面积节点
- 降低第三色饱和度或亮度
- 让主色承担视觉锚点

### Pattern 4: Radius Vibe Is Missing

现象:
主题整体很柔和，但 favicon 看起来还是“硬图形”

常见原因:

- 所有描边连接点都是尖角
- 高光切面过硬
- 内部细节线像机械刻线

常见修法:

- 保持轮廓不变，只调整 `linejoin` / `linecap`
- 把高光改成雾面反射，而不是白色切片
- 降低内部细节线的机械感

### Pattern 5: Small-Size Contrast Collapses

现象:
大尺寸 SVG 还行，但缩小后主体发灰、动势线发糊、节点不清楚

常见原因:

- 中间层太多，透明度叠加后变脏
- 主体和背景明度差太小
- 描边和填充色过于接近

常见修法:

- 减少中间透明层
- 提高主体与背景的明度差
- 让动势线和节点承担更明确的对比

## Theme Families Quick Notes

- `aurora`, `oled`, 一部分 `cyberpunk`:
  容易犯“整块主体过亮”的问题
- `clay`, `soft`, `wood`:
  容易犯“高光太白，失去材质温度”的问题
- `terminal`, `swiss`, `brutalism`, `blueprint`:
  容易犯“为了圆润统一而误伤硬边气质”的问题
- `zen`, `e-ink`, `sketch`:
  容易犯“过度提纯颜色，丢掉安静或手作气”的问题
- `kids`, `disco`:
  容易犯“所有颜色都很亮，结果没有主次”的问题

## When To Look At Other Favicons

适合横向对照的场景:

- 想确认当前主题是否沿用了项目共通的节拍器构图
- 想判断“布局是否需要保留”还是“其实整个系统都在用同一母版”
- 想看同一图形语言下，别的主题怎么分配主色和点缀色

不适合横向对照的场景:

- 把别的主题渐变、节点颜色直接搬过来
- 因为相邻主题好看，就让当前主题也变成同一气质

## Edit Guardrails

- 若用户未授权，不改 `path d`, `cx`, `cy`, `r`, `viewBox`
- 优先改色，再改质感，再改线条气质
- 每轮只解决最主要的 1 到 3 个问题
- 不为了“更统一”消灭主题个性
- 不为了“更像主题”损失 favicon 可读性
- 不把浏览器壳层颜色或其他站点图标资源是否同步，当作默认 review 结论的一部分

## Minimal Review Template

- 主题概念:
  3 到 5 个短点
- 结论:
  匹配 / 基本匹配 / 部分匹配 / 不匹配
- 主要问题:
  按严重度列出
- 问题类型:
  构图 / 配色 / 材质 / 圆角气质 / 小尺寸识别
- 修改策略:
  保留什么，改什么
- 验证限制:
  是否缺少 16x16 / 32x32 实际预览
- 范围说明:
  若本次只审 favicon，就明确说明未覆盖 `theme-color`、`apple-touch-icon`、manifest、PWA 图标

## After-Use Maintenance

- 如果某个主题家族反复出现同类问题，直接把该模式补进本 playbook
- 如果发现新的“CSS token 到 SVG 层”的稳定映射，也直接补进来
- 只沉淀会反复复用的判断，不记录单次审美偏好
