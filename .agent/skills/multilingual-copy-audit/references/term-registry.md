# Metronome Term Registry

这份表是项目文案统一的锚点。新增或修改稳定术语时，先改代码，再同步更新这里。

## Core Principles

- 同一功能优先保留一个稳定叫法。
- 标题和按钮可以更短，但不能换掉核心概念。
- 说明文案可以更白话，但不要把专业含义说偏。
- 若为了新手友好而换成更口语的说法，要保证仍能和真实控件名称对应上。
- 默认把所有已存在语言一起看，不只看中文。
- 各语言优先写成母语使用者会自然说出的产品文案，不追求逐词对译。

## Punctuation Rules

- 中文默认使用全角括号 `（ ）`。
- 英文及大多数西文默认使用半角括号 `()`
- 同一语言内不要混用两套括号。
- 同一组文案里的括号、冒号、引号风格要统一。
- 中文里若需要保留英文缩写，优先写成：
  `中文（TAP）`

## Preferred Terms

| Concept | Preferred Chinese | Notes | Avoid |
| --- | --- | --- | --- |
| BPM | `BPM` | 在控件名和技术语境里保留 `BPM`；解释时可说“速度” | `拍速`、`节奏速度` |
| BPM Note | `BPM 对应音符` | 描述里可解释成“BPM 对应哪种音符” | `BPM 基准音符` 与其它叫法混用 |
| Tempo Control | `速度调节` | 用于 Help 或说明标题；若真实控件是滚轮，描述里写“右侧滚轮”，不要沿用 `slider` | `BPM 速度控制` |
| Tap Tempo | `点按定速（TAP）` | 首次出现可保留 `TAP` | `点按速度` |
| BPM Memory | `常用速度` | 强调“保存常用值并快速切换” | `BPM 记忆栏` |
| Beat Bars | `节拍光柱` | 描述里可简称“光柱” | `节拍条`、`节拍柱` |
| Subdivisions | `节拍细分` | 说明里可写“每拍再分几份” | `小节细分` |
| Shift | `偏移` | 描述里可补“整体前移/后移” | `位移`、`移位` |
| Swing | `摇摆` | 描述里可补 `swing / shuffle 感` | 与 `偏移` 混成一个概念 |
| Speed Trainer | `速度训练` | 描述里可写“自动加速练习” | `速度渐变训练` |
| Interval Trainer | `间隔训练` | 描述里可写“播放 / 静音训练” | `间隔检测训练` |
| Presets | `预设` | 描述里可写“常用组合” | `预置`、`预设与曲目单` |
| Time Signature | `拍号` | 描述里可写“每小节几拍” | `节拍号` |
| Beat Unit | `单位拍` | 描述里解释成“每拍用什么音符表示” | 多个近义标签混用 |
| Sound | `音色` | 描述里可写“更容易听清的声音” | `声音预设` |
| Play / Pause | `播放 / 暂停` | 与快捷键说明保持一致 | `开始 / 停止` 与其混用 |

## Help Copy Patterns

- 标题优先写功能名，不写完整解释句。
- 说明优先写：
  “怎么操作” + “会发生什么”
- 若条目本身已经是专业词，说明里补一句白话解释。
- 若条目属于同一组，句式尽量保持平行。
- 若界面上是明确控件，如“滚轮”“光柱”“按钮”，说明里直接写真实控件名，不要写旧名称或泛称。

## Patterns To Avoid

- 一个地方写“音色”，另一个地方写“声音”，但其实指的是同一个控件。
- 一个地方写“细分”，另一个地方写“小节细分”，让人误以为范围不同。
- 同一功能的短标题和长说明完全对不上号。
- 为了显得专业而堆术语，结果新手看不懂。
